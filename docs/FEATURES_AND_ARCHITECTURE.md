# Pixiv Archive 功能与运行机制

本文档记录当前版本新增功能、扫描链路和资源占用优化，便于部署、测试和排查问题。

## 1. 图片扫描链路

### 增量扫描

手动扫描、watchdog 自动扫描和订阅下载后的扫描默认使用增量模式：

1. watchdog 收集变化的图片路径。
2. 防抖时间结束后，把变化路径交给扫描器。
3. 扫描器按文件名识别 Pixiv ID 和页码。
4. 同一作品的已入库页面会补回分组，用于保持页码、封面和作品数量正确。
5. 使用 `path + mtime_ns + size` 判断文件是否变化。
6. 未变化文件跳过数据库写入，不触发缩略图和元数据任务。

全量扫描仍会遍历目录，用于发现已经从磁盘删除的文件，但未变化文件同样会跳过数据库写入。全量扫描会执行缺失文件清理和完整重复候选刷新。设置页的“全量扫描”只影响扫描范围，不代表每个文件都会重复计算 hash。

### 页码和封面

页码以文件名中的 `p1`、`p2`、`p3` 为准，并按文件名页码排序。作品封面始终取排序后的第一页。

支持的典型文件名：

```text
作品标题 145672895 p1.png
作品标题 145672895_p2.png
作品标题 145672895-p3.png
作品标题 145672895p4.png
```

## 2. 去重与 IO 优化

普通扫描不会对每张图片计算 hash。去重流程分两阶段：

1. 扫描先按 `path + mtime_ns + size` 判断文件是否变化。
2. 同步元数据后，按数据库中的同一 Pixiv 作品和同一页码建立候选组。
3. 只有同一作品同一页存在多个本地文件时，才读取文件内容计算 SHA-256。
4. hash 相同的文件写入重复图片页面；hash 不同但仍属于同一作品同一页的候选写入怀疑图片页面，供检查不同分辨率、编码或裁剪版本。

Docker 默认使用：

```ini
PA_SCAN_HASH_MODE=off
```

这个值表示普通扫描不逐文件 hash，不代表关闭去重。候选组确认重复时仍会计算 SHA-256。不要改成 `always`，否则会对所有扫描文件读取完整内容。

重复页面默认勾选创建时间较晚的文件，便于保留最早文件；怀疑页面可自动勾选分辨率较低的文件。删除会先删除源文件，只有源文件删除成功后才清理数据库记录；删除失败时会保留记录并写入日志。去重日志记录候选组、实际删除结果和失败原因。

## 3. 并行任务管线

扫描任务启动后包含扫描、缩略图和元数据三个阶段：

```text
扫描入库线程
   ├── 缩略图有界队列 → 缩略图工作线程
   └── 元数据有界队列 → 元数据批处理线程
```

扫描线程发现作品后，会把需要处理的作品分别放入两个有界队列。缩略图和元数据可以并行处理，不互相等待；队列容量有限，避免一次性占用过多内存。数据库写入和元数据文件写入仍使用批次提交，以控制锁竞争和 IO 峰值。

相关配置：

| 配置 | 默认值 | 作用 |
|------|--------|------|
| `PA_SCAN_COMMIT_BATCH` | `8` | 扫描数据库批量提交数量 |
| `PA_SYNC_BATCH_SIZE` | `8` | 元数据同步批量作品数量 |
| `PA_METADATA_COMPACT` | `1` | 使用紧凑 JSON 保存元数据 |
| `AUTO_FAIL_PAUSE_ENABLED` | `1` | 连续失败后自动暂停 |
| `AUTO_FAIL_PAUSE_THRESHOLD` | `10` | 连续失败暂停阈值 |

SQLite 使用 WAL、`synchronous=NORMAL`、busy timeout 和有限缓存，减少 UI 查询与后台写入之间的锁冲突。

## 4. 自动监看与硬盘休眠

自动监看使用 watchdog 事件监听模式：

```ini
AUTO_WATCH_ENABLED=1
AUTO_WATCH_DEBOUNCE_SECONDS=30
AUTO_WATCH_POLLING=0
```

文件事件会在防抖窗口内合并。只有收到图片创建、修改或移动事件时才启动扫描，默认不会定时访问目录，因此不会因为监看功能持续唤醒硬盘。

`AUTO_WATCH_POLLING=1` 仅用于 NAS 或 Docker 环境无法传递文件事件的情况。轮询模式可能增加硬盘访问。

SSE 只负责向已打开的前端推送任务和刷新事件。SSE 断开后不会启动后台定时扫描；下次页面打开时重新建立 SSE 连接即可。没有页面连接时，后端不会因为 SSE 自身产生扫盘任务。

### 前端显示资源

画廊有两层资源控制：

1. `IntersectionObserver` 只加载视口上下约两个屏幕范围内的图片。
2. 画廊按当前排序、筛选和搜索结果，预热合并/展开模式切换所需的少量图片，缓存上限约 40 个条目。

当没有浏览器页面连接并达到 `PA_SSE_RELEASE_DELAY_SECONDS` 后，前端会释放已加载图片、预热缓存、查看器预加载和观察器资源。重新建立 SSE 后按需恢复，不会影响数据库和磁盘中的原图。此设置在界面中显示为“关闭显示窗口后释放前端资源”。

排查命令：

```bash
docker logs -f --tail=200 pixiv-archive
curl http://127.0.0.1:6814/api/watch/status
```

正常自动扫描日志通常包含：

```text
auto watch event queued
auto watch debounce elapsed; requesting incremental scan
auto scan using watchdog file list: files=N
incremental source walk finished
metadata_batch_done
```

## 6. 详情页与画廊显示

画廊始终优先使用缩略图，近屏范围外不加载图片资源。详情页先显示缩略图；启用“详情页自动显示原图”后，原图在后台完成加载才替换缩略图。详情页侧栏分为顶部导航、中间可滚动详情和底部固定操作区，底部固定显示原图、作品切换、收藏、打开原始文件夹和删除作品等操作。

展开页码模式下，图片切换跨作品边界时会自动进入相邻作品的第一页；从第一张向前切换时进入上一作品的第一页。相邻作品图片会提前预加载，以减少切换延迟。

## 7. 元数据、AI 和 R18

元数据同步只处理标题或同步时间为空、已删除、上次同步失败，或 `ai_type` 尚未识别的作品。手动“同步”是增量同步；设置页底部的“重建元数据”会强制处理全部作品。扫描发现新作品后，会把作品加入元数据队列，AI 状态与标签在同步完成后同时写入数据库，并用于 AI 筛选、角标和整理路径。

AI 分类优先使用 Pixiv 官方 `ai_type`：

- `2`：AI；
- `1`：Human；
- 缺失时仅使用明确的 AI 标记兼容规则。

R18 使用精确标签匹配 `R-18`、`R18`、`18R`，不会把 `R-18G` 误判为 R18。

## 6. 整理文件

整理功能与扫描目录独立，可以配置多个源文件夹和单独的输出文件夹。

支持复制、移动、软链接、硬链接、Shaft 风格路径模板、自定义模板、可选自动重命名、重命名模板和撤销最近一次整理。源目录可配置多个，输出目录独立于扫描目录。发生目标文件名冲突时，后续文件会按 `文件 (1).ext`、`文件 (2).ext` 递增命名；撤销时会清理本次创建的空目录。

整理路径模板变量（只生成目录）：

```text
{title}       作品标题
{id}          Pixiv ID
{author}      画师名称
{author_id}   画师 ID
{created:yyyy-MM}  创建日期
```

条件块：

```text
[?R18:R18/]
[?!R18:SFW/]
[?AI:AI/]
[?!AI:Human/]
```

重命名自定义模板变量：

```text
{filename}    原文件名
{title}       作品标题
{id}          Pixiv ID
{page}        当前页码
{pages}       作品总页数
{ext}         文件扩展名
{author}      画师名称
{author_id}   画师 ID
{w} / {h}     图片尺寸
{created:yyyy-MM-dd}  创建日期
```

整理路径模板只决定目录结构，不包含文件名。关闭“整理时自动重命名”时，文件名保留源文件名；开启后，文件名由重命名规则或重命名自定义模板决定。

## 7. Docker 部署注意事项

数据目录和图片目录建议分开挂载：

```yaml
volumes:
  - ./data:/app/data
  - "/你的图片目录:/app/data/images"
```

使用去重删除或移动整理时，图片目录必须以读写方式挂载，不能使用 `:ro`。只浏览和扫描时可以使用只读挂载。

容器内的 `/app/data` 应持久化挂载，否则重建容器会丢失数据库、缩略图、元数据、设置和日志。图片源目录建议单独挂载到 `/app/data/images` 或其它路径，并通过 `IMAGE_SOURCE_DIRS` 配置多个目录。

```bash
docker compose build --no-cache pixiv-archive
docker compose up -d
docker logs -f --tail=200 pixiv-archive
```

## 8. 持久化文件

`/app/data` 中主要包含：

| 文件或目录 | 作用 |
|------------|------|
| `archive.db` | SQLite 作品数据库 |
| `thumbnails/` | 作品缩略图 |
| `metadata/` | Pixiv 元数据 JSON |
| `.env` | 设置页保存的配置和 token |
| `organize_last.json` | 最近一次整理的撤销记录 |

升级前建议备份整个 `data` 目录。
